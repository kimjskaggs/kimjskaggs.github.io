Professional Self-Assessment

Completing the Computer Science program has helped me realize how much I have learned since I started. When I first began the program, I was mostly focused on learning how to code and getting my programs to work. As I moved through the different courses, I started to understand that there is a lot more that goes into developing software. I learned how important it is to think about how an application is designed, how data is stored and processed, how security is handled, and how the choices I make can affect the application later.

One of the biggest things I have learned is how to work through problems when I do not immediately know the answer. Throughout the program, I worked with different programming languages, tools, and types of projects. There were plenty of times when something did not work the first time, and I had to figure out why. I became much better at breaking a problem into smaller pieces, testing what I was doing, and making changes until I found a solution. I think that is one of the skills that will help me the most as I move into the computer science field because I know I am not going to know how to do everything right away.

Communication and collaboration were also important throughout the program. Even though a lot of my coursework was completed individually, I still had to think about other people when designing software. I had to work from requirements, explain the decisions I made, communicate technical information, and use feedback to improve my work. The code review for this capstone was a good example of that. I had to go back through an application I created earlier in the program, explain how it worked, identify areas that could be improved, and then use feedback throughout the course to continue improving it. That process helped me see code review as more than finding something that is wrong. It can also help make decisions about how software should continue to develop.

Throughout the program, I also gained more experience with algorithms and data structures. I learned how the way data is organized and processed affects what an application can do with it. I worked with sorting, searching, collections, and different ways of processing data to solve problems. I also became better at thinking about situations where the data may not look exactly the way I expect it to. This was something I continued working on during the capstone when I added calculations to my Weight Tracker application. Instead of only storing and displaying weight entries, the application now uses that history to calculate progress and provide more useful information to the user.

Software engineering and databases were also a large part of what I learned during the program. Earlier projects helped me learn how the different pieces of an application connect, while later coursework made me think more about how those pieces should be organized. I learned that making one change can affect several other parts of an application. I saw that again during the capstone when changes to the Weight Tracker required updates across activities, the repository, DAOs, database entities, layouts, and navigation. Working with databases also taught me to think about how records are related and what happens to existing data when a database changes instead of only thinking about how to save and retrieve information.

Security is another area where my thinking changed throughout the program. When I originally created the Weight Tracker, the login system was very basic and passwords were not protected the way they should have been. When I returned to the project for the capstone, I was able to recognize that as a problem and improve it. I added stronger password protection, validation, and testing. More importantly, I learned that security needs to be considered while software is being designed instead of being something that is added at the end.

The Weight Tracker application included in this ePortfolio brings a lot of these skills together. I originally created the application in CS 360: Mobile Architecture and Programming. For the capstone, I needed to select previous coursework to enhance, and I decided to use the Weight Tracker for all three enhancement areas instead of choosing a different artifact for each one. I liked that approach because it gave me the opportunity to take one application and improve it in several different ways. It also made it easier to see how changes in one area can affect other parts of an application. The software design enhancement improved the organization and authentication system, the algorithms enhancement added progress calculations and made better use of the user's weight history, and the database enhancement added measurements and goal history while expanding how the application's data is stored and managed.

The artifacts in this portfolio show that progression from the original application to the enhanced version. The code review shows where I started and what I identified as areas for improvement. The original and enhanced versions show the actual changes I made, while the narratives explain the reasoning behind each enhancement and what I learned while completing them. I think using one application for all three enhancement areas also shows how software engineering, algorithms, databases, and security are connected instead of treating them like completely separate parts of computer science.

Completing this program has made me more confident in my ability to enter the computer science field. I know that graduating does not mean I suddenly know everything there is to know about software development. What I do have now is a much stronger foundation and the ability to keep learning. I know how to approach a problem, work through it when something goes wrong, use feedback, and improve what I have already created. Those are skills I plan to continue building as I begin my career in computer science.
